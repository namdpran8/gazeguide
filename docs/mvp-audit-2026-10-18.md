## Check results

- Dataset audit: passed without changing project output. Rebuilt results match `assets/datasets/gazeguide-v1/dataset-report.json` exactly.
- Dataset contents: 90 candidates; 26 approved; 13 approved empty; 30 rejected; 34 pending; 26 copied images and 26 labels.
- Dataset quality: no cross-split near duplicates reported, but all nine visual classes are below the pipeline's 20-instance sufficiency threshold.
- Backend tests: failed before executing tests because the router cannot initialise with the currently installed dependency pair.
- API startup import: failed for the same reason.
- TV commands: test, lint and debug build were attempted from the repository root and failed because Node dependencies are not installed.
- Secrets check: no literal credentials identified in repository text outside Git sample hooks; this is not a substitute for a formal secret scan.

## Three highest-priority MVP tasks

1. **Make the backend reproducible and runnable.** Pin compatible FastAPI/Starlette dependencies, create a clean environment, get the complete backend test suite green and demonstrate `/health` plus `/api/v1/explain` fallback.
2. **Implement the actual TV learning flow.** Replace the starter tiles with lesson/scene/video selection, remote-focusable object regions and an explanation panel that visibly handles loading, retry, timeout and fallback.
3. **Make the demo legally and operationally usable.** Document video rights, add a root README/runbook, install/lock Node dependencies, and obtain a successful TV build. Dataset expansion can continue in parallel, but the current labels must not be used to train a detector.
